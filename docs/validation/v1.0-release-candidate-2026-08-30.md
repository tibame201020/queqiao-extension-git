- npm package: `@tibame201020/queqiao-extension-git`
- package version: `1.0.0`
- Queqiao extension identity: `dev.queqiao.git`
- extension manifest version: `1.0.0`

- Queqiao release commit used for final local acceptance: `cec8ad39dac5d1b1c83abcba6e1cd8218489722d`

The npm package identity intentionally differs from Queqiao's internal monorepo workspace package name. The runtime extension identity remains stable.

## Package boundary

The packed runtime imports no Queqiao implementation package. `@tibame201020/queqiao` is a development-only TypeScript contract dependency; runtime dependency is `zod` only.

Package metadata includes the Queqiao Extension API v1 manifest and declares seven Worker-hosted Git contributions:

- `git_repositories`
- `git_status`
- `git_diff`
- `git_log`
- `git_branches`
- `git_worktree_create`
- `git_worktree_remove`

Normal Extension Hub attachment uses Core Manifest Revision 7's fixed public `extension` proxy. Direct projection of the seven named public tools is an advanced deployment-manifest composition mode and is intentionally not implied by Worker attachment.

## Standalone integration validation

The standalone test suite uses the host OS Git executable against temporary real repositories and verifies:

- repository discovery;
- porcelain-v2 status;
- branch listing;
- commit log;
- bounded diff;
- contained worktree creation;
- worktree status;
- contained worktree removal;
- target path escape rejection;
- failed worktree creation cleanup;
- rejection of worktrees whose Git common directory is outside the authorized Workspace.

## Full Queqiao 0.8.1 acceptance

The final local acceptance used a temporary detached Queqiao `v0.8.1` worktree and temporary runtime directories. It did not modify Stable or Shadow runtime configuration.

Verified path:

```text
OAuth MCP client
-> Queqiao Gateway
-> fixed public extension proxy
-> Queqiao Worker
-> dev.queqiao.git
-> git_status
-> real temporary Git repository
```

Observed result:

```json
{"ok":true,"package":"@tibame201020/queqiao-extension-git","publicTool":"extension","extensionId":"dev.queqiao.git","capability":"git_status","workspaceId":"git-e2e-workspace","repositoryPath":"repo"}
```

The Extension Hub installed the packed scoped npm artifact through an ephemeral registry with lifecycle scripts disabled. The Worker Workspace was `coding` with `git` explicitly present in the command allowlist.

## Release automation

CI covers Windows and Ubuntu package/unit/integration gates plus Windows Queqiao 0.8.1 full acceptance.

`publish-npm.yml` is prepared for GitHub Release -> npm trusted publishing with provenance. It is idempotent for an already-published version. npm trusted-publisher setup requires the package to exist first, so the initial `1.0.0` package creation remains a one-time authenticated bootstrap; subsequent releases are intended to use OIDC trusted publishing.
